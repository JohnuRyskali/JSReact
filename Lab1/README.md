# Ответы на вопросы по JavaScript Core Concepts

### 1. Как замыкание (Closure) сохраняет приватность счетчика?
Функция `createTask` создает локальную переменную `let count = 0`. Методы `getCount()`, `reset()` и `run()` возвращаются в виде объекта и "запоминают" доступ к этой переменной даже после того, как `createTask` завершила свою работу. Из внешнего кода прямого доступа к `count` нет (например, `task.count` вернет `undefined`), что гарантирует приватность.

### 2. Как работает Call Stack (Стек вызовов)?
Call Stack работает по принципу LIFO (Last In, First Out — последним пришел, первым ушел). 
*Пример:* Когда вы вызываете `runSingleTask(0)`, функция помещается в стек. Внутри нее вызывается `task.run()`, которая становится поверх `runSingleTask`. Внутри `run()` вызывается `updateUI()`, которая кладется на самый верх. Когда `updateUI` завершается, она удаляется из стека, затем завершается `task.run()`, и наконец `runSingleTask`.

### 3. Как JavaScript продолжает работать во время ожидания setTimeout?
JavaScript однопоточен, но функции типа `setTimeout` передаются **Web APIs** (фоновому окружению браузера). Таймер отсчитывается браузером в отдельном потоке, не блокируя Call Stack. Когда время истекает, браузер помещает колбэк таймера в Task Queue (Очередь макрозадач).

### 4. В чем разница между Tasks (Макрозадачами) и Microtasks (Микрозадачами)?
- **Microtasks (Микрозадачи):** Колбэки `Promise.then`, `catch`, `finally`, тело `async/await`. Имеют наивысший приоритет.
- **Tasks / Macrotasks (Макрозадачи):** `setTimeout`, `setInterval`, события UI (`click`, `scroll`).
**Правило Event Loop:** После каждой синхронной операции Event Loop сначала опустошает **ВСЮ** очередь микрозадач, и только потом берет **ОДНУ** макрозадачу из очереди макрозадач.

### 5. Как обрабатываются ошибки при множестве Promises?
Если использовать `Promise.all()`, то при падении любого одного промиса весь запуск мгновенно прерывается ошибкой. 
В данном проекте используется **`Promise.allSettled()`**. Он ожидает завершения всех промисов независимо от того, выполнились они успешно (`fulfilled`) или с ошибкой (`rejected`), что идеально подходит для параллельного запуска независимых задач.

### 6. В чем разница между последовательным (Sequential) и параллельным (Concurrent) выполнением?
- **Sequential (`await task1; await task2;`):** Задачи выполняются по очереди. Общее время работы равно сумме всех длительностей ($T_{sum} = T_1 + T_2 + T_3$).
- **Concurrent (`Promise.all` / `Promise.allSettled`):** Задачи запускаются одновременно. Общее время работы равно времени самой долгой задачи ($T_{max} = \max(T_1, T_2, T_3)$).
